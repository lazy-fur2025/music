# 🎵 识曲窗口 (Music Recognition Overlay)

一个**实时歌词同步浮窗应用**，通过麦克风识别正在播放的音乐，自动获取歌词并与播放进度同步显示。

> 💡 **v2 改进版本**：修复了歌词加载失败、内存泄漏、UI 卡顿等核心问题，现已稳定可用。

---

## ✨ 功能一览

| 功能 | 说明 |
|------|------|
| 🎧 一键识曲 | 点击按钮，通过麦克风识别正在播放的歌曲 |
| 📄 自动获取歌词 | 查询网易云音乐 API 并同步显示 |
| 📊 实时频谱可视化 | 15 条音频频谱柱实时显示音量 |
| ✨ 流畅动画效果 | 渐变边框旋转、呼吸灯脉冲、文本淡入淡出 |
| ⏱️ 歌词时轴微调 | 鼠标滚轮前调/后调歌词播放时间（±0.5s）|
| 🪟 浮窗交互 | 置顶窗口，拖拽移动，无边框透明设计 |

## 🛠️ 系统要求

| 组件 | 版本 | 备注 |

## 📦 快速开始

### 1️⃣ 克隆/下载项目

```bash
git clone https://github.com/lazy-fur2025/music.git
```

### 2️⃣ 创建虚拟环境（推荐）

```bash
# Windows
python -m venv venv
venv\Scripts\activate

# macOS / Linux（不支持，仅供参考）
python3 -m venv venv
source venv/bin/activate
```

### 3️⃣ 安装 Python 依赖

```bash
pip install --upgrade pip
pip install -r requirements.txt
```

### 4️⃣ 启动歌词 API 服务（必需）

打开**另一个终端窗口**，运行：

```bash
npx NeteaseCloudMusicApi
```

> ⚠️ **重要**：这个服务必须在后台运行（默认监听 `localhost:3000`），应用才能获取歌词。
> 
> 如果看到类似 `Server running at localhost:3000` 的输出，说明服务已启动。保持这个窗口开着。

### 5️⃣ 启动应用

回到原来的终端，运行：

```bash
python Wow.py
```

应用会以小浮窗的形式出现在屏幕右上角。

## 🎮 使用说明

### 界面说明

```
┌─────────────────────────────────────────┬──┬──┐
│  点击红色按钮一次开始识曲，长按关闭       │🟡│🔴│
└─────────────────────────────────────────┴──┴──┘
```

| 区域 | 说明 |
|------|------|
| 左侧 15 条柱 | 实时音频频谱，显示当前播放音量 |
| 中间文字区 | 显示歌词（识曲中间也显示状态提示） |
| 🟡 黄色按钮 | 重置状态，停止当前识曲准备下一首 |
| 🔴 红色按钮 | **单击**开始识曲 / **长按**关闭窗口 |

### 操作流程

**场景：识别当前播放的歌曲**

1. 播放器里放上歌曲，调整到合适音量
2. 在浮窗上**单击红色按钮**
3. 等待 1-3 秒，应用会扫描播放器窗口、识别歌名、获取歌词
4. 识曲成功后歌词开始滚动同步

**场景：歌词显示不对时**

滚动鼠标滚轮微调歌词时间轴：
- 🖱️ **向上滚** → 歌词前调（更早出现）
- 🖱️ **向下滚** → 歌词后调（更晚出现）

每次调整 ±0.5 秒，浮窗会显示当前累计偏移量。

**场景：切换到新歌曲**

1. 单击**黄色按钮**重置状态
2. 播放新歌曲
3. 再次单击红色按钮识曲

## 🔧 故障排除

### 问题 1：启动后无法识曲（显示"未检测到播放源"）

**原因**：应用没有扫描到支持的播放器窗口。

**解决方案**：
- 确认使用的播放器在支持列表中（PotPlayer、Chrome、Edge、Firefox、网易云音乐）
- 确保播放器窗口标题包含"歌曲名 - 播放器名"的格式
  - ✅ 正确：`晴天 - PotPlayer`
  - ❌ 不支持：`无标题` 或 `Media Player`
- 试试切换到 Chrome 播放 YouTube 音乐或网易云

### 问题 2：启动后显示"无法连接歌词服务 (localhost:3000)"

**原因**：NeteaseCloudMusicApi 服务没启动或已崩溃。

**解决方案**：
```bash
# 重启服务
npx NeteaseCloudMusicApi
```
- 检查是否看到 `Server running at localhost:3000`
- 如果反复崩溃，试试更新服务：`npm install -g NeteaseCloudMusicApi@latest`
- 查看服务是否被其他程序占用端口 3000

### 问题 3：歌词加载了但显示很奇怪（乱码/重复/不同步）

**原因**：
- 网易云 API 返回的歌词格式异常或不完整
- 歌词时间轴与实际播放进度不一致

**解决方案**：
- 用鼠标滚轮手动微调对齐（见上面的"场景：歌词显示不对时"）
- 如果始终对不齐，说明这首歌的网易云歌词本身有问题（可能是非官方上传的版本）
- 试试搜索同一首歌的其他版本

### 问题 4：播放音乐时识曲很慢或经常失败

**原因**：
- 网络延迟或 API 服务缓慢
- 歌名特殊字符过多无法匹配

**解决方案**：
- 确保网络连接稳定
- 播放一些知名歌曲（网易云库里录入较多）
- 检查 NeteaseCloudMusicApi 服务日志是否有错误

### 问题 5：应用启动后麦克风常亮/电脑变卡

**原因**：麦克风驱动占用过多资源（旧版本有内存泄漏）。

**解决方案**：
- 使用最新版本的代码（v2 已修复此问题）
- 如果仍有问题，确保麦克风驱动是最新版本
- 关闭应用（长按红色按钮）会正确释放麦克风资源

## 📝 常见问题 (FAQ)

**Q：为什么一定要开 NeteaseCloudMusicApi？能用其他歌词源吗？**

A：当前版本依赖网易云的 API。理论上可以改成接入其他 API（如 QQ Music、Spotify），但需要改代码。欢迎提 Issue 讨论支持其他源。

---

**Q：支持 macOS/Linux 吗？**

A：不支持。代码用了 `pygetwindow` 来扫描播放器窗口标题，这个库仅支持 Windows。移植到其他系统需要替换窗口扫描方案。

---

**Q：能识别人唱的歌吗（不是播放器里的歌）？**

A：不能。应用是通过**识别歌曲元数据**（播放器窗口标题），而不是音频指纹识别。所以只能用在播放器里播放已有录音的场景。

---

**Q：歌词显示很延迟，怎么解决？**

A：这通常是因为播放器开启了缓冲或音频处理延迟。试试：
1. 用鼠标滚轮前调歌词（向上滚）
2. 如果总需要调，检查播放器的音频输出设置是否有额外处理

---

**Q：如何卸载/关闭应用？**

A：长按红色按钮 0.8 秒以上，会看到红色动画扫过屏幕，应用随即关闭。或者直接 Alt+F4。
